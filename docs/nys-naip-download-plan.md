# New York statewide NAIP download and compression

Resolution: **0.6 meters per pixel (1.6667 pixels per meter)**, the provider's native resolution. Acquisition year: 2022. Source: https://coastalimagery.blob.core.windows.net/digitalcoast/NY_NAIP_2022_9986/index.html

## Feasibility and limits

- All 3,805 source TIFFs appear in the three provider VRT indexes. Both SimpleSource and ComplexSource records must be included: omitting ComplexSource would miss 400 tiles.
- The indexes contain 439,663,608,400 pixels, or 1,318,990,825,200 bytes of raw RGB. At 10:1 this is 131.90 decimal GB. Actual JPEG sizes depend on scene content; a quality value does not guarantee a compression ratio.
- The source download is approximately 1,599.22 GB of losslessly compressed TIFFs. At most four temporary source TIFFs are retained at a time (largest listed source: 478.87 MB; less than 2 GB combined). RGB source reads use windows; compressed output is assembled in RAM.
- Start at JPEG quality 83. If necessary, retry a tile at quality 80, 77, then 75, always from the original pixels. Never change the resolution to fit storage. A tile must fit raw RGB bytes / 8 + 1 MiB, including its internal valid-data mask. Otherwise stop and report the tile rather than silently discarding it or reducing quality further.
- The sum of those tile ceilings is approximately 168.87 GB. This leaves substantial room under the **300,000,000,000-byte** folder limit for four source tiles, scripts, indexes, provenance, logs, and checkpoints. A shared guard serializes each check/write/account transaction before any controlled disk write grows a file and reserves 5 GB of the cap. Disk free space is also checked. This is a job-enforced limit on generated file bytes, not an operating-system quota against unrelated external writes into this folder.

## Execution plan

1. Keep every generated artifact under the selected job directory, defaulting to ignored `data/nys-naip-2022-rgb-060m`; keep source code, tests, and documentation in tracked repository folders. Reuse the existing repository Python environment, or install `requirements-nys-naip.txt` for acquisition only.
2. Snapshot the provider index and all three VRTs in the job directory. Build a manifest and require exact agreement between the download list and VRT tile names, dimensions, native CRS, and 0.6-meter spacing.
3. Test budget enforcement before writes, contained paths, atomic checkpoints, interrupted-download cleanup, missing-output resume, and georeferencing/mask preservation with small synthetic rasters.
4. Run a pilot covering Albany, dense urban imagery, and a rural northern tile. Verify full output decoding, RGB bands, dimensions, source transform, CRS, internal masks, checksums, and storage limits.
5. Start one locked background process with four tile threads for the full manifest. Each downloads a uniquely named tile, hashes it, reads RGB windows, compresses in RAM, validates the mask, writes through the shared budget guard, fully decodes and checksums the saved image, atomically publishes it, records provenance, and removes only its known temporary source file. Never queue more than four active tiles. Retry transient network failures. Resume completed tiles using provenance and output checksums.
6. Keep progress in status.json and events.jsonl, with two-second phase updates and a remaining-time estimate based on recent completion intervals from this worker session weighted by remaining pixels. These intervals measure aggregate throughput without double-counting overlapping task durations; exclude initial pipeline fill once enough samples exist. `scripts/download-nys-naip.ps1` starts/resumes and opens a live PowerShell monitor with overall and per-worker progress bars. If a process is active, the launcher attaches without creating a duplicate. A STOP file requests a clean pause. Restarting the launcher resumes the manifest and clears STOP. completion.json is written only after every tile has been verified. Temporary sharing violations on atomic writes are retried; a locked status file may briefly leave the display stale but cannot make provenance optional.

## Output and correctness

Outputs are tiled, three-band uint8 GeoTIFFs with JPEG/YCbCr compression and an internal lossless validity mask. Native NAD83 UTM zones 17, 18, and 19 are preserved; each has nominal 0.6-meter pixels. This avoids Web Mercator ground-scale variation and unnecessary reprojection. The collection is statewide, but not a single aligned statewide raster; source buffers overlap and are retained to avoid coverage gaps. Pixel spacing is not a claim of exact ground distance everywhere or perfect positional accuracy. RGB compression is lossy. Band 4 (NIR) is intentionally omitted.

The existing embedding program reads JP2 files and requires a single CRS per run. These GeoTIFFs will need a separate importer change or processing by CRS before embedding. No embeddings are generated by this download, and no existing imagery or embedding bundle is modified.

The provider lists unrestricted access/use and requests USDA-FSA attribution. Downloaded imagery stays in the ignored local job directory. See the [operating guide](nys-naip-download.md) for commands, output layout, attribution links, and offline tests.
